## 2. 环境准备：这里有一个必须先确认的条件

### 2.1 数据库备份/恢复是什么意思

同一学生先后导入，会更新招生和学籍记录；第二次还可能保留第一次部分字段。为了比较公平，两次都必须从相同初始数据开始。

- 优先使用独立测试库；若当前库仅为可重建模拟数据，也必须先确认用途、备份和恢复方案。
- 将准备好账号、元数据、基础维度，但没有E2样本的初始测试数据备份为S0。
- 每次正式任务前按事先确认的办法恢复S0，记录快照名、恢复时间和检查结果。当前论文要求相同初始状态，不采用先累计跑完30页OCR、再跑30页MLLM的办法。
- 修改文件名、立即截图、只在招生页面删除记录，不能代替恢复；学籍及其他关联数据可能残留。
- **本手册不授权清空原库，不在这里提供猜测性的恢复命令。先告诉我你使用的数据库工具，以及这个库是否含必须保留的数据；再单独确认准确操作。所有恢复操作（含P01试运行、E1及E2）都要先完成确认；未确认前只准备材料，不执行恢复或双路径导入。**

恢复前确认任务已经结束、证据保存完毕。恢复是否要停止/重启后端、如何检查连接和缓存，写入模板的“恢复确认单”，全部任务采用相同办法。磁盘文件、Redis和进程不随数据库备份自动恢复，不要擅自删除storage或清空共享Redis。恢复时间不计入识别耗时。

这一步会增加操作量，不能假装不存在。若以后希望减少恢复次数，需要先同步修改论文的实验设计，而不是悄悄改变比较条件。

### 2.2 先确认能用，不修改系统凑结果

1. 使用现有启动方式，确认登录、本地OCR、视觉模型、文本问答及嵌入服务能正常运行。
2. 填环境表：实际设备、软件版本、模型名、网络、运行方式和数据快照。模型未配置记阻塞，不写通过。
3. 检查模型账户余额；试运行、PDF、失败重试和问答都可能增加费用，不承诺固定成本。
4. 所有写入只在已确认测试环境做；正式数据不要上传给外部模型。
5. 在你自己的资料目录建立“论文实验_日期”，内设00_准备、01_功能、02_采集、03_问答、04_响应。记录不放在数据库或应用storage内，恢复后仍能保留。

### 2.3 结果怎么保存：浏览器即可

1. 按F12→网络/Network→Fetch/XHR，勾选保留日志。执行上传或查询后点对应请求→响应/Response。
2. 复制**响应正文**到记事本，保存UTF-8的JSON。不要分享整份HAR、请求头、Authorization、Cookie或登录响应。
3. 上传响应的`tasks[].taskId`是日志编号。到“OCR识别进程”看该任务；日志的`logId=taskId`，再记录`fileId`和来源文件。
4. 当日日志接口为`GET /api/ocr/log/today`。保存匹配日志的终态`recognizeStatus`；历史任务从“历史记录”查。
5. “数据管理→招生数据管理”的分页请求为`GET /api/admission/page`，结果在`data.records`，总数在`data.total`。清除全部筛选（关键词、培养层次、录入/更新时间），回第一页并保存所有分页，之后用fileId/来源文件确认当次结果。当前该分页接口没有fileId过滤参数，不要猜参数。
6. 不只搜索正确学号：错学号、额外行也要保留。一次只处理一页，文件名唯一，关联不清就保存全部结果让我核对。
7. 命名如`D01_OCR_01_上传.json`、`D01_OCR_01_终态.json`、`D01_OCR_01_业务_第1页.json`。恢复后taskId可能重复，必须同时使用run_id标识。

顶栏有“脱敏”开关，但这是后端实例级开关，不仅影响你自己。**仅当整个实例全是模拟数据且无其他用户使用时**，才可通过已有开关观察完整模拟值，重新查询后保存，并在结束时恢复原状态。真实数据或共享环境不要关闭。仍显示星号就记“不可观察”，不能拿星号评分；先确认取证方式再正式测试。

## 3. 材料与6页试运行

准备P01—P06，建议三层各2页，每页5条虚构记录，6页都分别尝试OCR和MLLM，共12次试运行，不计入正式成绩。可复用这些材料做E1，但不加入正式30页。

建议先在“系统管理→元数据管理”核对以下6个字段的现有规则。用表格软件制作名册，导出/截图为单页图像；不需要训练数据集。

|编码|图像列名例|招生响应字段|固定规则|
|---|---|---|---|
|student_no|学号|studentNo|12位模拟编号；按文本保存，保留前导零|
|name|姓名|name|虚构2—4个汉字；仅去首尾空白|
|gender|性别|gender|男/女；空白也标注|
|province_name|省份|provinceName|用系统已有名称；上传省份留空|
|admission_date|录取日期|admissionDate|优先完整YYYY-MM-DD；上传年份留空|
|admission_score|录取分数|admissionScore|按整数值比较|

“档案智能采集”只提供招生/毕业上传类型，招生会同步学籍。招生必须选择培养层次，例如学士；这类手工输入不计入主识别成绩。只有图像/PDF显示“LLM 智能提取”开关，CSV/XLSX不参与双路径。

先运行P01并保存两路结果，确认字段可观察、任务可追踪、S0可恢复。之后完成其余试运行，再冻结字段、参数及观察时长。失败原因先确认，不能带着取不到结果的问题直接跑正式实验。

正式30页每页5条、6字段时，至少900个字段真值、两路至少1800个字段核对。这是计划工作量，统计可以交给我，但人工核对不能省去。

## 4. E1：18项逐条执行

用独立的模拟功能名单，不与E2正式样本混用。每项填写输入、预期、实际、结果和证据位置；以下预期不是已经测试通过。

|编号|执行步骤|通过条件/证据|
|---|---|---|
|F01|测试账号＋当前验证码登录|进入主页面；不保存凭据|
|F02|错误验证码；再验证已消费验证码不可重复登录|两分项均拒绝。重复分项需在本人测试环境用网络工具重放同一验证码请求；用新图片不能替代。不会重放就注明分项未执行，本项阻塞，不反复试密码|
|F03|上传5条已知招生记录CSV|字段和记录正确；保存输入、终态、结果|
|F04|另一组5条招生记录XLSX；打开学籍页面|招生与同步学籍均可核对，保存两边结果|
|F05|清晰图像关闭LLM上传|终态和业务字段正确，保存原结果|
|F06|恢复同一起点，同页开启LLM上传|选路正确、终态和业务字段可核对|
|F07|两页不同名单组成PDF，关闭LLM|两页记录均可核对，不能只看第一页|
|F08|恢复起点，同一PDF开启LLM|保存页进度和两页最终记录|

|F10|毕业档案上传与已有模拟学号匹配的毕业记录|毕业数据及学籍毕业状态正确|
|F11|长任务处理中在OCR识别进程点击取消|cancelled终态及本地任务停止；保存后续无继续处理的观察、后台日志或相关进程结束证据。仅有“已取消”截图不证明进程停止，不会确认就注明并交我核对；不保证云端停止计费|
|F12|上传无表格图像或可控损坏测试文件|明确失败/警告且不伪报正确；若成功但零记录，如实记实际并按条件判失败|

|F15|知识库上传无敏感TXT|ready且块数大于0，保存TXT和列表|
|F16|清空对话，问该TXT明确事实|返回完整可检查答案；内容评分另见E3|
|F17|智能报告生成选实验年份，生成并打开A3打印视图|数字同口径一致、无明显裁切；保存两种视图|
|F18|编辑一名模拟学生录取日期到另一年份，再查询年度统计|其他数据不变时原年减1、新年加1；保留前后值及时间。只改姓名不会改变人数|

最终只用“通过/失败/阻塞”。已执行但仅部分符合预期记失败，“部分满足”只写备注；未能执行完整必要分项记阻塞并列原因。实际失败不能改叫阻塞。通过率=通过数÷实际执行数，同时报告计划18、通过、失败、阻塞；分母0记NA。

F02重复验证码的具体做法：在F01登录前打开F12网络并保留日志；成功登录后，找到本人的`POST /api/login`请求，右键选择“Replay XHR/重新发送XHR”（浏览器提供该功能时），原请求不改、不重新取验证码，只重发一次。应得到验证码失效的拒绝响应，而不是新的登录令牌。保存第二次的拒绝信息即可，不保存首次登录响应或包含密码的请求体；已有登录页面仍然打开不代表重复请求成功。没有重发菜单时先告诉我浏览器名称，不能把更换验证码后的请求当作重复测试。错误验证码分项另取新验证码，故意输入一个错误值测试一次即可。

## 5. E2：30页正式比较

### 5.1 运行前完成真值

1. D01—D30三层各10页：清晰规则表格；清晰但复杂版式（分组表头、标题常量、列顺序差异等）；仍可人工辨认的退化图像（轻度模糊、倾斜或低对比度）。
2. 每页至少5条，明确标注模拟/真实及许可。保存来源和处理说明；同原页变体共用family_id，不冒充独立材料。试运行材料不与正式样本重叠。
3. 逐格记录原文、规范化值和来源状态。原文缺日、输出补01属于规则补全，不算完整日期被识别正确。空白也记录。
4. 请同学独立复核全部真值；只有自己时至少隔一天重新核对，并记单人复核限制。
5. 固定字段、上传参数和S0。随机打乱doc_id，保存顺序；按**运行顺序奇偶**交替OCR先/MLLM先，不分成两个累计批次。正式后不改规则、不按结果重分层。

### 5.2 每页照这个顺序做

1. 按已确认流程恢复S0，检查无进行中任务，记恢复时间。
2. 建run_id，例如D01_OCR_01；开启录像/计时。所有时间来自同一电脑/同一录像时间轴。
3. 选招生、培养层次、图像，按预定顺序设LLM开关；一次只选本页文件。
4. 点击开始上传前记t0；收到含taskId响应记t1，保存上传JSON。可用网络请求开始时间＋请求总耗时求t1，但不要混用另一台机器的时钟。
5. 在OCR识别进程首次观察到success/warning/failed/cancelled记t2，保存日志和录像时间点。上传返回不等于识别完成。
6. 保存全部分页业务结果，包含错行、额外行和部分结果；按taskId→日志→fileId/来源核对。填写运行表。
7. 确认证据在数据库之外保存完毕，恢复同一S0，上传**相同文件字节**，换另一条路径，重复步骤2—6。
8. 核对两份任务记录、业务输出和真值齐全，再进行下一页。重试编号02并填retry_of，不替换首次结果。

提交耗时=t1−t0；完整任务耗时=t2−t0，按秒记录。3秒轮询存在观察误差，不报告毫秒级识别精度。恢复和人工整理时间不算识别时间。

正式前根据试运行约定统一最大观察时长并记录。任务未结束不能凭空填t2；达到该时长需取消时记录取消原因和时间，单列超时/取消并计入失败统计，不算正常完成，不删样本。

### 5.3 核对与计分

先将预测行与真值行一对一匹配：学号正确优先；学号错误可人工按位置/其他字段判断，但不改预测。匹配不上输出记extra，真值未出现记missing，重复输出不能重复匹配。

|字段情况|TP|FP|FN|
|---|---|---|---|
|原文明确且输出完全正确|1|0|0|
|原文明确但输出错误非空|0|1|1|
|原文明确但输出空白/遗漏|0|0|1|
|原文空白但输出非空|0|1|0|
|原文空白且输出空白|0|0|0|
|不可辨认/不可观察/规则补全/人工补充|NA|NA|NA|

排除项必须分别注明原因和数量。额外行的非空评测字段计FP，遗漏的可评真值字段计FN。整页失败且没有任何业务输出时，全部可评真值字段计FN。有部分入库时，已产出字段按上表计分（错误非空仍计FP和FN），未产出的可评真值字段计FN；页面失败状态另记，不能再整页追加FN。不能同一字段重复计FN，也不丢掉额外行。

完整记录率=全部可评字段正确且无额外非空评测字段的真值记录数÷可评真值记录总数。**含不可辨认或不可观察字段的记录排除并报告数量；失败页不能从分母删除。** 人工补充和规则补全不混入主指标；没有任何主评字段的行记NA，不算完整正确。

P=TP/(TP+FP)，R=TP/(TP+FN)，F1=2TP/(2TP+FP+FN)，分母0记NA。先加总计数再算，不直接平均三层百分比。你可以先填原文、输出及判定，计数和指标交给我复核。

### 5.4 费用和错误案例

- 保存批次起止、模型名、正式页数、额外调用、账单；无法隔离批次费用写NA，不按网络单价造结果。OCR没有视觉API费不代表没有本机和人工成本。
- 目标至少4个代表错误案例，关注行错位、表头误配、标识误读、无依据补全。没出现某类写“未观察到”，不制造四类错误来凑数。
- 保存各层/整体字段结果、完整记录率、失败页数、成功与失败耗时。图5-3不用误差线也可以，后续由我绘制真实数据图。

## 6. E3：知识和数据问答

### 6.1 先写资料、问题和答案

1. 用5份TXT即可（论文允许5—8份），固定标题、版本、段落编号。模拟规则明确标模拟，不冒充真实校规。
2. 在“AI 智能→知识库”上传，等ready且有块数。**当前检索查全部ready资料**；保存实际全部资料清单，不忽略已有资料。混有其他数据就先确认测试准备方案，不擅自删除。
3. 预先写K01—K15单段题、K16—K25多依据题、K26—K30范围外题；每题写标准要点、必要标题和段落，范围外题确认资料确实无答案。
4. 另写B01—B10数据库题，从固定模拟业务记录人工核对真值：指定年份人数、层次、专业/省份分布、毕业状态等。保留清单和筛选口径，不拿AI结果当答案。
5. 知识题统一附“请依据知识库资料回答并给出资料标题；资料不足时明确说明”。这是实验提示，不保证模型不联网。

### 6.2 每次回答

1. 上一回答结束后点AI助手的“清空对话”，确认历史为空。
2. 开启录像/计时，发固定问题。记录发送、首个服务端状态和完整答案到达时间。
3. 页面立即出现的“正在分析问题”是前端提示，不能直接算服务端首状态；分不清首状态填NA，完整答案时间照常记录。
4. 保存完整原回答为TXT/Markdown，保存工具过程状态、截图、时间，不只截最后半段。
5. 保存后清空再问同一道知识题一次，用K01_R1/K01_R2编号。30题共60次；10道数据库题各一次，共70次。
6. 报错/无完整答案保留首次记录；重试另编号。不要只保留较好回答，也不要用其他模型替答。

### 6.4 评分与分母

|知识题分数|标准|

|2|必要要点完整，没有实质错误|
|1|部分要点正确，没有关键事实错误|

### 7.1 确定请求

### 7.2 创建最小测试计划

在Test Plan下添加一个Thread Group，下设**一个**HTTP Request、HTTP Header Manager、JSON Assertion和Simple Data Writer。调试时可加View Results Tree，正式前禁用；不添加HTTP Cache Manager、登录或其他请求。

- HTTP Request：GET；Protocol、Server/IP、Port分别按实际地址填。Path选上面一个；招生页参数current=1、size=15填参数表。连接超时5000ms、响应超时15000ms，这是实验设置。
- HTTP Header Manager：Authorization=本人临时值。
- JSON Assertion：Path=`$.code`，勾选Additionally assert value，Expected Value=`200`，不选正则。本项目普通查询成功码为200；HTTP200但业务失败也须判失败。
- Thread Group：Ramp-up=1秒，采样错误选Continue，Forever不勾，不加额外循环控制器。
- Simple Data Writer：每轮全新CSV。Configure中选CSV、保存字段名及至少timeStamp、elapsed、label、responseCode、success、threadName、failureMessage；不要保存请求头、响应头、正文或Sampler Data。

JSON断言用法已按[Apache JMeter官方说明](https://jmeter.apache.org/usermanual/component_reference.html#JSON_Assertion)核对：路径存在且值为200才通过。这里是测试配置，不是已完成压测。

### 7.3 每轮怎么跑

1. 先1线程循环5次，输出到独立“预访问”文件，确认正常返回；不计入正式100次。
2. 设置档位：1线程×循环100，5线程×循环20，10线程×循环10。每线程只运行一个HTTP请求，合计才是100。
3. 换正式CSV名，例如dashboard_c1_r1.csv；开始，结束后检查实际100条并记录轮次时间。
4. 同档重复3轮，每轮先5次预访问、再100次正式请求，每次换新文件。
5. Dashboard完成三个档位共9轮，再换招生分页完成9轮，合计18份正式CSV、1800次计划请求。
6. 不同时上传、提问、预测或更新数据，关闭OCR等轮询页面；记录数据规模、缓存、同机/远程及后台负载。

认证过期就保留本轮并标环境中断，重新登录另起轮次并关联；不能覆盖。持续超时/明显影响正常使用则停止，记录实际请求数和原因。不要提高并发或改系统凑数字。

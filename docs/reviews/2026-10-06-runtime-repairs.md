# 运行问题修复与验证

日期：2026-10-06。按用户讨论修复运行问题，不进行安全改造、不引入人工复核、不修改数据库结构。

## 修复内容

1. CSV/Excel 的上传补充信息：省份、入学日期、学历填充缺失、null 或空白值，保留文件已有有效值。补充在必填/类型校验之前生效，避免值已补齐仍提示缺失。测试覆盖 CSV 与真实构造的 XLSX。
2. 元数据来源字段：前端必填并禁止纯空白；新增、更新接口返回明确的参数提示；导入遇到非法历史配置给出明确配置错误，不再抛无说明的空指针。实查 public.metadata_standard.source_field 已设置 NOT NULL，现有数据无 null/空白，未修改数据库。
3. 用户不支持 .tif：前端选取/拖放与后端存储入口都拒绝，上传阶段就提示不支持；未增加 .tif OCR 处理能力，保留原有 .tiff 支持。
4. 跨日期终态：依据原上传路径对应的 archive/failed 结果主动结束日志，不再依赖“只扫描今天目录”。保留原始失败原因。扫描仅补充无日志的历史文件，不覆盖已有任务，避免轮询把 warning/cancelled 改写成 success/failed；排除警告侧边文件。
5. 首页专业分布：使用一次不限制年份的聚合查询，包括早期、新年份和日期缺失的已关联专业数据。页面标注“全部年份”，识别并绕过旧范围缓存。年度报表的年份筛选保持不变。
6. 取消一致性：取消决策与入库入口共用任务锁。解析阶段取消成功后，即使底层库清除线程中断，也不能继续入库；开始入库后拒绝取消，直至任务退出。处理取消后才注册的子进程会被销毁。前端检查业务响应，拒绝取消不再显示“取消成功”，并说明入库后不可取消。
7. 缓存一致性：文件事务提交后再次清除维度和首页缓存，避免事务提交前被其他请求回填的旧缓存长期存在；回滚不触发提交后回调。

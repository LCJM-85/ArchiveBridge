# 4.6 OpenCV Linux 路径修复记录

- 日期：2026-09-10
- 对应问题：`PROJECT_AUDIT_ISSUES.md` 4.6
- 处理范围：Docker/Linux 下 OpenCV 图片增强脚本的大小写路径
- 数据库影响：无

## 1. 问题核对

问题成立，证据如下：

- Git 跟踪的真实脚本是 `src/main/python/openCV/opencv.py`。
- `OpenCVService.java` 原先构造的路径是 `src/main/python/opencv/opencv.py`。
- Dockerfile 使用 `COPY src/main/python ./src/main/python`，会保留 Git 中的 `openCV` 大小写。
- Windows 默认不区分文件名大小写，所以本地可能正常；Linux 区分大小写，因此容器中会找不到脚本，随后回退到未增强的原图。

## 2. 修复方案与代码变更

采用最小修改：保留现有 Python 目录，将 Java 中的脚本路径改为与 Git/Docker 完全一致的大小写。

```text
修复前：src/main/python/opencv/opencv.py
修复后：src/main/python/openCV/opencv.py
```

没有选择在 Windows 上做仅大小写的 Git 目录重命名，因为那种变更更容易受 `core.ignorecase` 和不同文件系统影响。修改 Java 的一处字符串更简单，且不改变 Python 包结构。

### 变更文件

- `scau-archive-insight/src/main/java/edu/scau/scauarchiveinsight/service/OpenCVService.java`
  - 修正 `ProcessBuilder` 使用的 OpenCV 脚本路径大小写。
- `scau-archive-insight/src/test/java/edu/scau/scauarchiveinsight/service/OpenCVServiceLinuxPathTest.java`
  - 新增回归测试，捕获 `OpenCVService` 实际构造的子进程命令。
  - 断言脚本参数以 `/src/main/python/openCV/opencv.py` 结尾，避免 Windows 文件系统将错误大小写掩盖。

## 3. 测试记录

### 失败复现

修改生产代码前运行：

```text
mvn -Dtest=OpenCVServiceLinuxPathTest test
```

结果：1 项测试失败。实际命令为 `.../python/opencv/opencv.py`，预期为 `.../python/openCV/opencv.py`。这证明测试直接覆盖了 4.6 的根因。

### 修复后验证

| 验证项 | 结果 |
|---|---|
| `mvn -Dtest=OpenCVServiceLinuxPathTest test` | 1 项通过，0 失败 |
| Java 全量 `mvn test` | 29 项，0 失败，0 错误，1 跳过 |
| 工作树空白检查 `git diff --check` | 通过 |

全量测试中跳过的是需要显式启用的 Redis 真实集成测试，与 OpenCV 路径无关。Spring 上下文测试中 AI Python 子进程仍因本机缺少 API 凭据而退出，但 Java 测试和 Spring 上下文通过；这不是本次 OpenCV 路径修改引入的错误。

## 4. 影响和未验证边界

- Windows 本地路径仍可用；Linux/Docker 现在会指向镜像内真实存在的 `openCV/opencv.py`。
- 本次没有改动接口、前端、数据库、Dockerfile 或 Python 脚本逻辑。
- 回归测试验证了 Java 生成的真实命令参数，但本次未构建完整 Docker 镜像，也未在 Linux 容器内跑真实图片增强。因此只确认“脚本路径大小写已一致”，不将 Python/OpenCV 系统依赖表述为已做容器端到端验证。
- 如果后续容器中 `import cv2` 报系统动态库错误，那是独立的 Docker/OpenCV 依赖问题，不应再归因于本次已修正的大小写路径。

## 3. 高优先级问题

### 3.1 上传路径缺少边界校验，可能写出存储目录

- 位置：`StorageService.java:48-53`、`ArchiveUploadController.java:52-61`。
- 事实：接口直接使用用户传入的 `type` 拼接目录，并直接把 `MultipartFile.getOriginalFilename()` 拼接为目标路径；没有规范化后检查目标路径是否仍位于允许的存储根目录。
- 影响：已登录用户可构造包含绝对路径或 `../` 的参数/文件名，把上传内容写到 `storage` 目录之外，严重时可能覆盖应用可写文件。
- 建议：`type` 改为后端枚举；文件名只保留 `Path.getFileName()`；对最终路径执行 `normalize()`，并强制校验 `target.startsWith(storageRoot)`；服务端生成随机存储名。

知识库上传接口 `KnowledgeController.java:37-39` 也存在同类文件名问题，需要一并处理。

### 3.2 知识库处理接口可接收任意服务器本地路径

- 位置：`KnowledgeController.java:54-70`、`KnowledgeService.java:36-50`、`ai_assistant/rag/document_loader.py:39-43`。
- 事实：客户端可直接提交 `filePath` 和 `fileType`，后端把该路径交给本地 Python 读取；没有验证该文件是否来自本系统的 `storage/rag` 上传目录。
- 影响：已登录用户可能把服务器上的可读文本文件导入知识库，再通过知识库查询间接读取内容。
- 建议：客户端只提交上传记录 ID；后端从数据库解析实际路径，并校验真实路径位于 `storage/rag` 下。

### 3.3 “记住密码”把明文密码保存到 localStorage

- 位置：`scau_archive-frontend/src/utils/auth.js:38-40`、`:72-75`。
- 事实：用户名和原始密码直接写入浏览器 `localStorage`。
- 影响：XSS、恶意扩展、共享电脑或浏览器调试均可能直接取得账号密码；风险高于仅泄露短期 Token。
- 建议：不要保存密码，只保存用户名；登录保持应依赖受保护的会话/刷新令牌，而不是保存原始密码。

### 3.4 登录限流信任可伪造的代理请求头

- 位置：`LoginController.java:155-164`、`docker-compose.yml:50-51`。
- 事实：代码无条件优先采用 `X-Forwarded-For`、`X-Real-IP`，同时 Compose 将后端 `8080` 直接发布到宿主机。
- 影响：攻击者直接访问后端时可以自行修改请求头，轮换限流键并绕过按 IP 的验证码和登录限制。
- 建议：仅在请求确实来自受信任反向代理时解析代理头；否则使用连接来源地址。生产部署可只向前端代理网络暴露后端端口。

## 4. 中优先级问题

### 4.1 CORS 范围过宽

- 位置：`SecurityConfig.java:61-70`。
- 事实：允许 `http://*:*`，同时启用了 `allowCredentials=true`。
- 影响：当前使用 Bearer Token，风险尚低于 Cookie 自动认证，但配置不适合生产环境；以后若改为 Cookie，会明显扩大跨域攻击面。
- 建议：按环境配置明确的前端来源白名单，开发和生产配置分离。

### 4.2 服务重启只修改日志，不迁移遗留文件

- 位置：`OCRLogService.java:162-169`。
- 事实：启动后会把遗留 `processing` 日志改成 `failed`，但没有把相应文件从 `storage/temp` 移到 `storage/failed`。
- 影响：日志状态与文件位置不一致，临时目录会遗留孤立文件；前端显示失败但失败目录找不到该文件。
- 建议：启动恢复时逐条处理任务，在状态更新和文件迁移之间建立可重试、可审计的恢复流程。

### 4.3 取消任务存在状态和文件迁移竞态

- 位置：`OCRLogController.java:69-79`、`OCRTaskManager.java:51-59`。
- 事实：接口先把日志改为 `cancelled`，再取消进程并迁移文件；文件迁移异常被忽略，且任务可能在取消同时完成归档。
- 影响：接口可能返回“已取消”，但文件未进入 `failed`，甚至任务已经完成；日志、文件和真实进程状态可能不一致。
- 建议：明确任务状态机，使用条件更新避免终态互相覆盖；取消结果应检查 Future/Process 和文件迁移结果。

### 4.4 processingCount 仅存在 JVM 内存

- 位置：`StorageService.java:25-34`、`:70`、`:86`、`:125`、`:165`。
- 事实：处理中数量由 `AtomicInteger` 维护，服务重启后归零，也没有从数据库任务状态重建。
- 影响：重启、异常分支或并发取消可能导致计数与真实任务数不一致；多实例部署时各实例看到的计数不同。
- 建议：处理中数量直接查询任务日志表，或使用数据库/Redis 中可恢复的任务状态，不以 JVM 计数作为事实来源。

### 4.5 删除日志按文件名递归删除多个目录

- 位置：`OCRLogService.java:184-209`。
- 事实：删除日志时会在整个 `storage` 中递归删除所有同名文件及侧边错误文件。
- 影响：若文件名发生碰撞，删除一条日志可能误删另一任务的文件；异常被忽略后，接口仍可能显示删除成功。
- 建议：日志表记录规范化后的唯一文件路径或文件 ID，删除时只处理这一明确目标。

### 4.6 Docker 中 OpenCV 目录大小写不一致

- 位置：`OpenCVService.java:21`；实际目录为 `src/main/python/openCV`。
- 事实：Java 使用小写 `opencv`，Windows 不区分大小写所以可运行；Linux 容器区分大小写。
- 影响：Docker 下图片增强脚本找不到，代码会退回原图，OCR 仍可能完成但质量下降。
- 建议：统一目录名和代码路径，并加入 Linux 容器中的图片增强集成测试。

### 4.7 PDF 转图片子进程可能阻塞且错误信息不足

- 位置：`ArchiveUploadController.java:138-151`。
- 事实：先完整读取标准输出再等待进程结束，没有消费标准错误，也没有检查退出码和超时。
- 影响：子进程大量写入标准错误时可能阻塞；脚本退出失败时可能只表现为 JSON 解析错误，难以定位。
- 建议：合并或并发消费输出流，设置可取消的超时，检查退出码，并在 `finally` 中注销进程。

## 5. 环境、测试与维护风险

### 5.1 当前 WSL Redis 未启用密码

- 当前进程、用户和系统环境均未设置 `REDIS_PASSWORD`。
- Redis 真实测试在未认证情况下通过，说明当前 `127.0.0.1:6379` 接受无密码连接。
- 如果 Redis 只监听本机，风险有限；如果 WSL 或端口转发允许局域网访问，则属于未授权访问风险。
- Docker Compose 支持可选密码，但本地 WSL Redis 和 Docker Redis 是两个独立实例，配置不会自动同步。

### 5.2 Maven Wrapper 在当前 Windows PowerShell 环境不可用

- `.mvnw.cmd` 在本机执行时出现脚本数组索引错误。
- 使用全局 Maven `3.9.11` 可以完成全部测试。
- 影响：README 中的 Wrapper 启动方式不能保证新环境开箱即用。

### 5.3 前端产物体积偏大

- Vite 构建成功，但主 JavaScript 文件约 2.6 MB，超过默认分块警告阈值。
- 影响：首页加载、解析和低性能设备体验可能较差。
- 建议：路由懒加载、拆分 ECharts/Element Plus 等大依赖，并按页面验证实际加载体积。

### 5.4 测试覆盖边界

- 当前自动测试主要覆盖 Spring 上下文、Redis 缓存契约、验证码原子消费和缓存清理。
- 尚无上传路径安全、取消竞态、重启文件恢复、Docker OCR、真实文件处理、浏览器端登录安全和端到端流程测试。
- 因此“8 个测试全部通过”只能证明现有测试覆盖范围内通过，不能推出整个系统无 Bug。
